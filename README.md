# Техническое задание

Необходимо реализовать сервис проверки ссылок на актуальность. То есть приходит запрос с ссылками и нужно вернуть какие из них актуальны, а какие нет.

## API

Сервис должен принимать HTTP запросы

### Запросы
#### Запрос на проверку ссылок

```bash
POST /api/links
```

**Заголовки**

```bash
Content-type: application/json
API-KEY: ...
```

Если ```Content-type``` не  ```application/json```, то необходимо вернуть **415 Unsupported Media Type** статус HTTP.

API-KEY задается в .env, он необходим, чтобы сервис понял, является ли клиент своим или нет. Если код невалидный, то запрос откланяется, и сервис возвращает **403 Forbidden** статус HTTP.

**Тело запроса** 

```json
{
    "links": [
        "google.com",
        "ya.ru",
        "github.com",
        "vk.com"
        "invalid.url.com"
    ]
}
```

Количество ссылок в запросе может быть очень большим, сервис должен исскуственно ограничить количество ссылок в запросе, этот параметр должен задаваться в .env. 

```bash
MIN_LINKS_AMOUNT=1
MAX_LINKS_AMOUNT=20
```

Если количество ссылок невалидно в запросе необходимо возвращать **413 Payload Too Large** статус HTTP.

**Заголовки ответа**

```bash
Content-type: application/json
```

**Тело ответа**

```json
{
    "links": [
        {
            "link": "google.com",
            "status": true
        },
        
        {
            "link": "ya.ru",
            "status": true
        },
        {
            "link": "github.com", 
            "status": true
        },
        {
            "link": "vk.com", 
            "status": false
        },
        {
            "link": "invalid.url.com", 
            "status": false
        }
    ]
}
```

HTTP статус ответа должен быть **200 OK**


#### Запрос на количество самых популярных запрашиваемых ссылок

```bash
GET /api/links?limit=5
```

**Заголовки**

```bash
API-KEY: ...
```

Запрос приходит с ```query``` параметром limit, которое является числом, и должно быть больше нуля обязательно. Если ```limit``` невалиден: строка или меньше нуля или вообще не задан, то нужно вернуть **400 Bad Request**. Важно, хранить ссылки в ```map```, или в ```sync.Map```

**Заголовки ответа**

```bash
Content-type: application/json
```

**Тело ответа**

Например, ```limit=4```

```json
{
    "links": [
        {
            "link": "google.com",
            "amount": 25
        },
        
        {
            "link": "ya.ru",
            "amount": 10
        },
        {
            "link": "github.com", 
            "amount": 7
        },
        {
            "link": "vk.com", 
            "amount": 3
        }
    ]
}
```

HTTP статус ответа должен быть **200 OK**

#### Запрос на состояние сервиса

```bash
GET /api/health
```

**Заголовки**

В данном запросе нет заголовков.

HTTP статус ответа должен быть **204 No Content**

## Технические подробности

- Сервис должен быть написан на чистом ```net/http```

- Проверка ```API-KEY``` должна проверяться в ```middleware```

- Нельзя использовать СУБД, только ```map```, ```sync.Map```

- Нужно ограничить время проверки одной ссылки(использовать context), то есть она должна быть не дольше 1-2 секунд. Можно задать в .env

- Запросы на ссылки должны отправляться конкуретно (использовать горутины, их количество ограничить с помощью семафора)
